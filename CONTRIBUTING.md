# Contributing to GarlicSMTP

Thank you for your interest in contributing to GarlicSMTP.

GarlicSMTP is a source-available project maintained by
Giuliano Signorelli.

The official GarlicSMTP source code is made available under the
PolyForm Noncommercial License 1.0.0. Separate commercial licenses
may be granted by the copyright holder.

Because GarlicSMTP uses this licensing model, contributions must
follow the rules described below.

## Contributor License Agreement

Code contributions are accepted only from contributors who agree
to the GarlicSMTP Contributor License Agreement contained in
`CLA.md`.

By submitting a pull request containing a contribution, you must
explicitly confirm that you have read and agree to the CLA.

A pull request must contain the following statement:

    I have read and agree to the GarlicSMTP Contributor License
    Agreement (CLA.md), and I have the right to submit this
    contribution under those terms.

Contributions for which this confirmation is missing must not be
merged into the official GarlicSMTP codebase.

## Copyright

You retain copyright ownership of your original contribution.

The CLA grants the GarlicSMTP maintainer the rights necessary to
use, modify, distribute, sublicense, and relicense accepted
contributions, including as part of separately licensed commercial
versions of GarlicSMTP.

## Original Work

You may submit only material that:

- you created and have the right to license;
- you are legally authorized to contribute; or
- is clearly identified as third-party material together with its
  applicable copyright and license information.

Do not submit code copied from another project without clearly
identifying its origin and license.

Do not submit code generated from material whose license or
provenance is unknown or incompatible with GarlicSMTP.

## Third-Party Dependencies

Do not introduce a new third-party dependency without identifying:

- the project name;
- the upstream project location;
- the applicable license;
- whether the dependency is required at runtime, for the GUI, for
  development, or only for testing.

Dependencies with copyleft, source-disclosure, noncommercial,
commercial, or otherwise restrictive licensing requirements must
be reviewed before they are accepted.

## Pull Requests

Contributions should normally be developed in a separate branch or
fork and submitted as a pull request.

Acceptance of a contribution is at the discretion of the GarlicSMTP
maintainer.

Submission of a contribution does not guarantee that it will be
merged.

## Security Issues

Potential security vulnerabilities should not be disclosed in a
public issue before the maintainer has had a reasonable opportunity
to investigate them.

See `SECURITY.md` for the project's vulnerability reporting policy.
